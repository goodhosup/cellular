# 무선 인터페이스 AI/ML

!!! spec "스펙 · 릴리즈"
    연구: TR 38.843 (Rel-18, AI/ML for NR air interface) · 망 AI: TS 38.300 §16.20 (Rel-18 NG-RAN AI/ML), TR 37.817 · 핵심망: TS 23.288 (NWDAF) · Rel-19: 빔 관리·측위 규격화, CSI 예측, LCM 일반 절차
    Rel-17 RAN3 연구 → Rel-18 무선 연구 + RAN3 규격 → Rel-19 무선 규격화(1단계) → Rel-20 확장 → 6G AI-native

!!! basic "한눈에 보기"
    지금까지 이동통신의 신호 처리는 사람이 수식으로 설계했습니다. 5G-Advanced부터는 일부를 **학습된 AI 모델**로 바꾸는 작업이 표준에 들어오고 있습니다.

    대표적인 활용 예 세 가지:

    1. **CSI 압축·예측**: 단말이 채널 정보를 AI로 **압축해서 보고** → 피드백 비트를 줄이면서 정확도는 높임. 미래 채널을 **예측**해 고속 이동에서도 정확한 빔포밍
    2. **빔 관리**: 빔 64개를 다 재지 않고 **몇 개만 재서 나머지를 추론** → 측정 시간·전력 감소
    3. **측위**: 다중경로가 심한 공장에서도 **채널 패턴으로 위치를 학습** → cm~m 단위 정확도

    표준은 AI 모델 자체를 정하지 않습니다. 대신 모델을 **어떻게 학습·배포·감시·교체할지**와 **입출력 형식**을 정합니다.

## 유스케이스 { .l2 }

| 유스케이스 | 모델 위치 | 입력 → 출력 | 기대 효과 | 표준화 단계 |
|---|---|---|---|---|
| **CSI 압축** | **양측** (단말 인코더 + 기지국 디코더) | 채널 → 잠재 벡터 → 복원 채널 | 같은 오버헤드에서 정확도 ↑ (Type II 대비) | 연구 계속 (상호운용 쟁점) |
| CSI 예측 | 단말 | 과거 CSI → 미래 CSI | 고속 이동 시 CSI 노화 보상 | Rel-19 규격 |
| **빔 관리 (공간)** | 단말 또는 망 | 일부 빔 측정 (Set B) → 전체 빔 중 최고 (Set A) | 측정 RS·보고 감소 | **Rel-19 규격** |
| 빔 관리 (시간) | 단말 또는 망 | 과거 빔 측정 → 미래 최고 빔 | 빔 전환 지연 감소 | **Rel-19 규격** |
| **측위 (직접)** | 단말 또는 LMF | CIR/PDP 등 → 위치 | NLOS 환경 정확도 ↑ | **Rel-19 규격** |
| 측위 (보조) | 단말 또는 gNB | 측정 → LOS/NLOS, 보정된 TOA | 기존 방식 정확도 ↑ | **Rel-19 규격** |

## 모델 수명 주기 관리 (LCM) { .l2 }

```mermaid
flowchart LR
    D[데이터 수집<br/>학습용 · 추론용 · 모니터링용] --> T[모델 학습<br/>오프라인, 표준 밖]
    T --> R[모델 등록·식별<br/>Model ID / 기능 ID]
    R --> A[활성화 · 비활성화<br/>전환 · 폴백]
    A --> I[추론]
    I --> M[성능 모니터링<br/>지표 · 기준값 비교]
    M -->|성능 저하| A
    M -->|재학습 필요| D
```

| 개념 | 의미 |
|---|---|
| **기능 기반 LCM** | 망은 "어떤 기능(예: 빔 예측 8→64)을 쓸지"만 관리, 구체 모델은 단말 구현 |
| **모델 ID 기반 LCM** | 망이 특정 모델을 식별·지시 |
| 협력 수준 | Level x: 협력 없음 / y: 시그널링 기반 협력 / z: 모델 전송까지 |
| 일반화 | 학습 환경과 다른 셀·단말 배치에서 성능 유지 여부 — 모니터링·전환이 필요한 이유 |

## 망(RAN·핵심망) AI { .l2 }

| 영역 | 규격 | 내용 |
|---|---|---|
| NG-RAN AI (Rel-18) | RAN3 | 에너지 절감, 부하 분산, 이동성 최적화를 위한 **예측 정보 교환**(Xn/NG) |
| NWDAF (Rel-15~) | SA2 | 망 분석: 부하·QoS·이동성 예측, 모델 학습 기능 분리(MTLF), 연합 학습 |
| 관리 (OAM) | SA5 | AI 모델 학습·배포·성능 관리 |

??? expert "전문가 노트 — 평가 결과와 표준화 쟁점"
    **CSI 압축 평가 (TR 38.843 요지).** 여러 회사 시뮬레이션에서 Rel-16 eType II 대비 같은 오버헤드에서 평균 SGCS(코사인 유사도) 향상과 수 % ~ 10% 수준의 처리량 이득이 보고되었습니다(시나리오·가정에 따라 편차가 큼). 그러나 양측 모델은 **단말 인코더와 기지국 디코더를 누가 어떻게 맞출지**(Type 1 공동 학습 / Type 2 순차 학습 / Type 3 각자 학습 + 데이터셋 공유)가 상호운용의 핵심 쟁점입니다.

    **빔 예측 이득.** Set B(예: 8개 측정)로 Set A(예: 32–64개) 최고 빔을 맞히는 Top-1/Top-K 정확도가 높게 나와, RS 오버헤드·측정 지연을 크게 줄일 수 있음이 확인되었습니다. 단말 측 모델은 단말 회전·차단 패턴 학습에 유리하고, 망 측 모델은 다수 단말 데이터를 활용합니다.

    **시험 가능성(RAN4).** 학습된 모델의 성능을 어떻게 인증할지가 어렵습니다. 기준 데이터셋·기준 모델·시험 채널 모델 정의가 함께 논의됩니다.

    **6G AI-native.** 6G에서는 AI를 전제로 한 참조신호 설계, AI 기반 수신기, 모델 배포 프레임워크(데이터·모델 전송 계층) 등 더 근본적인 통합이 연구됩니다. → [6G 후보 기술](../sixg/key-technologies.md)
