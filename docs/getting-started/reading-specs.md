# 스펙 문서 읽는 법

!!! spec "참고 문서"
    TR 21.900 (3GPP 작업 방법), TR 21.905 (용어 정의 Vocabulary)

!!! basic "한눈에 보기"
    3GPP 규격은 수천 개 문서로 되어 있지만 **번호 규칙**만 알면 원하는 문서를 쉽게 찾을 수 있습니다.

    - **36.xxx** = LTE 무선 (E-UTRA)
    - **38.xxx** = 5G NR 무선
    - **23.xxx** = 시스템 구조 (핵심망 절차)
    - **24.xxx** = 단말–핵심망 프로토콜 (NAS)

    예를 들어 TS 36.211은 LTE 물리 채널, TS 38.211은 NR 물리 채널 문서입니다. 뒤 세 자리가 같은 역할을 하도록 맞춰져 있습니다.

## 문서 종류 { .l2 }

| 종류 | 의미 | 예 |
|---|---|---|
| **TS** (Technical Specification) | 구현해야 하는 규격. 상호운용의 기준 | TS 38.331 (NR RRC) |
| **TR** (Technical Report) | 연구 결과, 평가, 옵션 비교. 구속력 없음 | TR 38.901 (채널 모델), TR 38.912 (NR 연구) |

| 단계 | 내용 | 예 |
|---|---|---|
| Stage 1 | 서비스 요구사항 | TS 22.261 (5G 요구사항) |
| Stage 2 | 전체 구조와 기능 설명 | TS 36.300, TS 38.300 (RAN 개요), TS 23.501 (5G 구조) |
| Stage 3 | 비트 단위 프로토콜·절차 | TS 38.331, TS 24.501 |

!!! tip "처음 읽을 문서"
    무선 쪽은 **Stage 2 개요 문서**(LTE는 TS 36.300, NR은 TS 38.300)부터 읽으세요.
    전체 구조를 설명하고 세부 규격으로 가는 길을 알려줍니다.

## 원문 찾는 법 { .l2 }

1. 3GPP 사이트의 **Specifications** 메뉴에서 번호로 검색하면 모든 버전이 나옵니다.
2. FTP 아카이브 `Specs/archive/38_series/38.211/` 에 버전별 zip 파일이 있습니다.
3. 파일명 규칙: `38211-i30.zip` → TS 38.211 **V18.3.0**
    - 버전 숫자는 0–9, 그다음 a=10, b=11, … i=18, j=19 처럼 문자로 씁니다.
4. 같은 내용은 ETSI에서도 `ETSI TS 138 211` 형태 번호로 PDF를 공개합니다.

??? expert "전문가 노트 — 스펙을 효율적으로 읽는 요령"
    - **"shall" / "should" / "may"**: shall은 필수, should는 권장, may는 선택입니다. 단말 구현 여부를 판단할 때 중요합니다.
    - **ASN.1에서 시작하기**: RRC 파라미터가 무슨 뜻인지 궁금하면 TS 38.331의 ASN.1 정의 → *field descriptions* 표 → 물리계층 규격(38.213/214) 순서로 따라가면 빠릅니다.
      필드 설명에 "see TS 38.213 clause 10.1" 같은 참조가 있습니다.
    - **Need 코드**: RRC 필드 옆의 `Need M`(유지), `Need R`(해제), `Need S`(명시된 기본 동작), `Need N`(유지하지 않음)은
      필드가 빠졌을 때 단말이 어떻게 해석하는지 정합니다. 재구성(reconfiguration) 디버깅의 단골 원인입니다.
    - **Change Request(CR) 추적**: 특정 동작이 어느 버전에서 바뀌었는지는 3GPP 포털의 CR 목록과 각 회의의 Tdoc으로 확인합니다.
    - **UE capability와 같이 보기**: 규격에 있는 기능도 단말이 capability로 보고해야만 망이 설정할 수 있습니다(TS 38.306 / 38.331 `UE-NR-Capability`).
    - **회의 기록(Chairman's notes)**: 규격 문장이 모호할 때 RAN1 회의의 *Agreements*를 보면 의도를 알 수 있습니다.
